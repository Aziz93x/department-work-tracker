# قسم التقنية الكهربائية — النسخة المحلية

نسخة محلية فعلية بواجهة عربية RTL. لم يُعتمد اسم تجاري للمنصة.

## التشغيل

افتح `تشغيل-المنصة.cmd` من هذا المجلد. يبدأ الخادم مخفيًا ويفتح http://127.0.0.1:5173.
بيانات حسابات التجربة موجودة في `.local/حسابات-الاختبار.md`. لا توجد حسابات افتراضية ثابتة في كود التطبيق، ولا تُنشأ الحسابات تلقائيًا عبر واجهة عامة. كلمات مرور التجربة عشوائية ومخصصة لهذه النسخة المحلية.

عند توفر Node.js 22.13+ وnpm على جهاز آخر:

```sh
npm ci
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 migrations apply DB --local --config wrangler.local.json --persist-to .wrangler/state
node scripts/seed-local.mjs
npm run dev -- --hostname 127.0.0.1 --port 5173
```

لا تعِد توليد المخطط دون تغييرات؛ ملفات الترحيل في `drizzle/` معتمدة ومطبّقة. أضف ترحيلات جديدة للتعديلات التالية.

## المنفذ

- React/Vinext + TypeScript وواجهة عربية RTL، مع مكونات Shadcn/Radix ومخطط قاعدة بيانات Drizzle.
- قاعدة SQLite محلية فعلية عبر محاكي D1؛ جميع بيانات التطبيق في الخادم وليست localStorage.
- دخول باسم المستخدم وكلمة المرور، بصمات scrypt مع salt عشوائي (N=16384,r=8,p=5)، جلسة 8 ساعات، رمز جلسة عشوائي يُحفظ مجزأ في قاعدة البيانات، وملف ارتباط HttpOnly / SameSite=Strict (Secure عند HTTPS).
- حد للمحاولات الفاشلة: 8 محاولات لكل اسم حساب خلال 15 دقيقة، وفحص Origin وCSRF لكل تعديل.
- رئيس القسم: إدارة جميع حسابات القسم، إنشاء حسابات، تغيير الأدوار والتفعيل وإعادة تعيين كلمات المرور، تعديل أي ملف شخصي عبر API، والاطلاع على المؤشرات، ورفع الشواهد للمدربين ومراجعتها.
- المدرب: ملفه ومؤشراته الخاصة فقط، مع فرض الملكية في الخادم.
- الوكيل والعميد: مؤشرات إجمالية فقط؛ لا قوائم مستخدمين أو ملفات شخصية أو تقارير رايات، ولا تعديل أو رفع.
- إنهاء جلسات الحساب فور إيقافه أو تعديل دوره أو كلمة مروره، ومنع الرئيس من إيقاف نفسه أو إزالة دوره الإداري، وحماية آخر رئيس نشط.
- لوحات افتراضية للرئيس والمدرب والقيادات. بداية بسيطة لتخصيص العرض: إظهار/إخفاء المؤشرات والكثافة، محفوظة لكل حساب؛ الحقول الإضافية مثل قيم المؤشرات مرفوضة. بقية خيارات العرض المتقدمة لاحقة.
- صفحة «تقارير رايات» مستقلة للرئيس، تدعم تقارير SF01 وSS01 وSL03 وSO01 وSO08 وSF06. تُفحص الملفات قبل حفظها في المخزن الخاص، وتظهر ملخصات دون بيانات شخصية. أزيل تقريران ST09 وSF20 من المنصة بطلب المستخدم، مع الإبقاء على الملفات الأصلية خارجها.
- لوحة القسم تعرض أعداد المتدربين الفريدة في حالات الانسحاب وطي القيد والحرمان بحسب SF01، وعدد من لا تسجيل لهم بحسب SF06. الرئيس يدير مبادرات عامة وخطط تحسين للحالات الثلاث ويرفق شواهدها؛ القيادات تقرأ المؤشرات فقط.
- كشف SL03 المحلي المصحح يستبعد سجلين أُدرجا خطأً وفق تأكيد رئيس القسم. يظل المدرب المكلف للتدريب عن بُعد ضمن شعب SS01 ومؤشراتها، ولا يُحسب عضوًا في كشف SL03. أكد رئيس القسم أن الشعبتين 65557 و65559 تُدرّسان عن بُعد رغم وصفهما «نظري صباحي» في المصدر؛ يحفظ النظام الملف كما صدر ويحسبهما ضمن مؤشرات التدريب عن بُعد للفصل 144710. عند إعادة تصدير SL03 من رايات يجب مراجعة هذين السجلين قبل اعتمادهما مجددًا.
- صفحة «الشواهد»: الرئيس يختار مدربًا نشطًا ويرفع الشاهد باسمه، والمدرب يرفع الشاهد الخاص به فقط. يحتفظ النظام بالنسخ والمراجعات السابقة وباسم من رفع كل نسخة. الرئيس وحده يحدد «مجتاز» أو «غير مجتاز». الملف خاص في مخزن R2 المحلي؛ تنزيله يمر دائمًا عبر التحقق من الجلسة والصلاحية. الصيغ المدعومة حاليًا PDF وPNG وJPG وWebP حتى ١٠ ميغابايت، مع التحقق من ترويسة المحتوى.
- صورة شخصية للرئيس والمدرب، بحد ٢ ميغابايت وبالصيغ PNG/JPG/WebP، تُعرض بجوار اسم صاحب الحساب وفي الملف الشخصي. الوكيل والعميد يحتفظان بصلاحية القراءة فقط.
- سجل عمليات للحسابات والدخول وتغييرات الملف وتفضيلات العرض، دون كلمات مرور أو قيم الحقول الشخصية.
- جداول أساس للمقررات والشعب والمتدربين والالتحاقات، بلا واجهات إدخال أو بيانات حقيقية. الاستعلامات تحسب الأعداد وتقيّد المدرب بشعبه. حسابات التجربة مستبعدة من عدد المدربين.

## خريطة الملفات

- `app/platform.tsx`: واجهات الدخول واللوحات والحسابات والملف ورايات.
- `app/rayat-page.tsx` و`lib/rayat.ts`: صفحة رفع تقارير رايات وفحص ملفات CSV وملخصاتها.
- `app/rayat-indicators.tsx` و`app/department-actions.tsx`: مؤشرات الحالات ومبادرات القسم وخطط التحسين وشواهدها.
- `app/api/[...path]/route.ts` و`lib/api.ts`: واجهة الخادم والصلاحيات المركزية.
- `lib/security.ts`: كلمات المرور ورموز الجلسات.
- `lib/contracts.ts`: الأدوار والتحقق من مدخلات الحسابات والعرض.
- `db/schema.ts` و`drizzle/`: الجداول والترحيلات.
- `scripts/seed-local.mjs`: تهيئة تجريبية صريحة محلية فقط.
- `scripts/test-integration.mjs`: اختبارات السيناريوهات الفعلية للخادم.
- `scripts/test-rayat.mjs`: فحص محلل CSV وصلاحيات رفع رايات والحفظ، مع تنظيف ملف الاختبار الاصطناعي.
- `scripts/test-department-actions.mjs`: فحص المبادرات والخطط والشواهد وصلاحياتها وتنظيف بيانات الاختبار.
- `scripts/verify-restart.mjs`: إثبات الحفظ بعد إيقاف الخادم وتشغيله من جديد.
- `scripts/test-evidence.mjs` و`scripts/verify-evidence-restart.mjs`: فحص الرفع والتنزيل الخاص والمراجعة وحفظ الملفات بعد إعادة التشغيل، ثم تنظيف بيانات الاختبار.

## حفظ البيانات

**المجلد `.wrangler/state` يحتوي قاعدة البيانات وملفات الشواهد والصور وتقارير رايات المرفوعة لهذه النسخة المحلية؛ لا تحذفه باعتباره ملفات مؤقتة.**
إغلاق المتصفح أو إعادة تشغيل الخادم لا يحذف البيانات. `.local` يحتوي كلمات مرور الاختبار وسجلات التشغيل المحلية؛ لا تنشره ولا تضمّنه مع المصدر. قاعدة البيانات تحت `.wrangler/state/v3/d1` وملفات R2 تحت `.wrangler/state/v3/r2`.
للنسخة الاحتياطية المحلية استخدم تصدير D1 المحلي أو أوقف الخادم ثم انسخ مجلد `.wrangler/state` كاملًا. انسخ المصدر وملفات الترحيل بصورة منفصلة. لم تُنفذ إدارة النسخ الاحتياطي أو استعادة الإنتاج في هذه المرحلة.

## الاختبارات

```sh
node node_modules/typescript/bin/tsc --noEmit
npm run build
node scripts/test-integration.mjs
node --experimental-strip-types scripts/test-rayat.mjs
node scripts/test-department-actions.mjs
# أوقف عملية الخادم ثم أعد تشغيلها، دون حذف .wrangler/state
node scripts/verify-restart.mjs
node scripts/test-evidence.mjs
# أوقف عملية الخادم ثم أعد تشغيلها
node scripts/verify-evidence-restart.mjs
```

الاختبارات مصممة للنسخة المحلية ذات قاعدة البيانات الأكاديمية الفارغة وحسابات التجربة. تنشئ صفوفًا اصطناعية مؤقتة ثم تزيلها؛ لا تشغّلها على قاعدة بيانات حقيقية. ملخص التشغيل الفعلي في `TEST-REPORT.md`. تفاصيل النتائج في `test-results/`.

## حدود المرحلة

تظهر مؤشرات SF01 وSF06 وملخص الغياب من SO01 في لوحة القسم، مع فصل نطاق شعب القسم عن جميع مقررات متدربيه. لا تتضمن التقارير المعتمدة الآن إجماليًا موثوقًا لمتدربي القسم حسب المستوى؛ لذا لا يمكن حساب نسبة التسجيل إلى إجمالي القسم أو تفسير الفرق القديم بين ST09 وSF01 داخل المنصة. لم تُدمج بعد بيانات رايات الفردية مع جداول العمل المحلية أو لوحة المدرب.

نُشرت نسخة خاصة على Sites للاختبار، بقاعدة سحابية مستقلة وفارغة عن قاعدة الجهاز المحلي. يوجد حساب أولي لإدارة النسخة وحسابات اختبار للأدوار؛ بيانات دخولها محفوظة محليًا في `.local/sites-test-accounts.json` ولا تُضمّن مع المصدر. لا تُرفع تقارير رايات أو بيانات القسم إلى Sites تلقائيًا. قبل التشغيل الفعلي يلزم إدخال البيانات المعتمدة، إعداد النسخ الاحتياطي، ومراجعة ضوابط الاستضافة. المصادقة مستقلة باسم مستخدم وكلمة مرور؛ لا يعتمد التطبيق على هوية ChatGPT أو Microsoft 365.
